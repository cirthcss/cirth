HTML-native CSS framework

Cirth

Production-ready UI from semantic HTML.

Cirth turns native HTML elements into accessible, themeable interfaces. Load one stylesheet, customize it with runtime design tokens, and ship with zero JavaScript and no required build step.

Proof, not promises

A production-ready baseline, out of the box.

Every number below is checked automatically, on every build — not a claim you have to take on faith.

<14KB gzipped

The default stylesheet is a strict maximum limit for gzip compression during each build; failing that, the build fails.

0 JavaScript

Accordions, dropdowns, and modals run on native <details> and <dialog> behavior. Nothing shipped, nothing to hydrate.

WCAG 2.2 AA

Contrast, visible focus rings, and 44px touch targets are checked in the source, not left to integrators to add later.

244 tokens

Every color, spacing, radius, and font is a runtime --cirth- custom property, overridable without a rebuild.

01

Semantic HTML first

Standard elements — nav, article, button, table, details — carry the styling. Add a class only where HTML semantics run out.

  • <nav>
  • <article>
  • <button>
  • <table>
  • <details>
02

Fully customizable theme

Every color, spacing, radius, font, and shadow is a --cirth- custom property. Override them after loading the framework — no build step, no Sass.

  • --cirth-primary
  • --cirth-spacing
  • --cirth-border-radius
  • custom properties
03

Classless & scoped builds

Ship the default build, a classless build for markup close to zero, or a scoped build that only styles inside a .cirth container.

  • Default
  • Classless
  • Scoped
  • Scoped + classless
04

Light and dark out of the box

The default theme ships light and dark variants, switching automatically with prefers-color-scheme or forced with data-theme.

  • prefers-color-scheme
  • data-theme
05

Interactive without JavaScript

Accordions, dropdowns, and modals build on native <details> and <dialog> elements and their native behavior — no runtime, nothing to hydrate.

  • <details>
  • <dialog>
06

Accessible by default

Visible focus rings that survive Windows High Contrast, 44px touch targets, and prefers-reduced-motion / prefers-contrast support are checked in the source, not bolted on after.

  • forced-colors
  • 44px targets
  • prefers-contrast

Questions

Before you install

Do I need to write any JavaScript?

No. Cirth ships zero JavaScript. Accordions, dropdowns, and modals are native <details> and <dialog> elements, styled by the framework and driven by the browser's own behavior.

Is a build step required?

No. Add one <link rel="stylesheet"> (or one import in a bundler) and standard elements are styled. SCSS exists in the repository to produce the compiled output; it isn't a public Sass API you need to compile yourself.

How big is the default stylesheet?

<14KB gzipped, currently. Every build is checked against that budget on every commit by a script that gzips the real output and fails the build if any bundle crosses it.

Which browsers are supported?

The latest stable Chrome, Edge, Firefox, and Safari (desktop and iOS), compiled against that exact Browserslist target with Lightning CSS. No version of Internet Explorer is supported.

How is this different from Pico CSS?

Cirth started as a fork of Pico CSS. It now has its own package name, a reduced single-theme color system, a runtime token surface, and a WCAG 2.2 AA baseline checked in the source — see the full comparison.

Is Cirth affiliated with the Tolkien estate?

No. The name references the real-world Cirth runic alphabet as a design metaphor for the framework's size constraints, not a license or partnership — see Brand.

What license is Cirth under?

Apache License 2.0 for the code. The name and logo are separate brand assets with their own terms, documented on the Brand page.
